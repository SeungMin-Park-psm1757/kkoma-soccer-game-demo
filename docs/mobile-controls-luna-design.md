## 3. 코드에서 확인한 문제

줄 번호는 위 작업 SHA 기준이다. 수정 시 함수 이름으로 다시 찾는다.

| 문제 | 근거 | 수정 방향 |
|---|---|---|
| 공개 게임 이동이 중간에서 멎음 | main의 pointermove: `pointer.origin + delta * min(1,14/length)` | 연속 이동이 있는 최신 브랜치를 기준으로 검증하고 배포 버전을 구분 |
| 최신 브랜치도 필드 끝 여유 폭이 큼 | game.js 381~389: 목표 y를 3~102로 제한 | 월드 경계와 화면 UI 영역을 분리. 필드 선수 경계를 한곳에서 정의 |
| 안내선이 실제 선수/목표를 따라가지 않음 | pointermove에서만 game.aim 계산, drawAim은 저장된 시작점 사용 | 움직이지 않는 손가락도 매 프레임 현재 선수·동료·카메라 기준으로 안내 갱신 |
| 놓은 위치가 패스 대상 선택에 직접 쓰이지 않음 | gestureMetrics/resolveGesture 725~745: 시작점 대비 벡터, passTargetFor: 방향 점수 | 손끝 가까운 동료를 우선 후보로 보고, 없을 때 방향 자동보정 |
| 슛이 패스를 과도하게 우선함 | resolveGesture가 동료 탐색보다 먼저 슛 판정, 슛 사거리 조건 없음 | 명확한 동료 지정을 우선하고 슈팅 구역·상대 골대 방향을 함께 검사 |
| 골키퍼 배급이 시작되지 않음 | updateMatch 397~400: GK 이동 뒤 continue, 소유자 패스 처리에 진입하지 않음 | 골키퍼 소유 전용 1초 타이머와 자동 배급 처리 |
| 골킥이 구현돼 있지 않음 | 496~503: 골대 바깥 골라인 통과 시 반사 및 lastTouch 반전 | 명시적인 골킥 대기/재개 처리, 1초 후 실제 kick 호출 |
| 태클 체감 거리와 추격이 불일치 | tryManualTackle 즉시 5.2, 추격 접촉 2.8, 추격 0.75초 | 접촉 반경을 하나로 통일하고 충분한 추격 시간을 부여 |
| 태클/추격 후보에 GK 포함 | nearestPlayer/nearestPlayers는 role 필터 없음 | 수비 압박·수동 태클 후보는 필드 선수로 제한 |
| 수비 후 손을 놓자 공을 다시 참 | finishPointer가 터치 시작 상황 없이 현재 소유자만 검사 | 수비로 시작한 입력은 탈취 후에도 공격 킥으로 해석하지 않음 |
| 득점·하프타임 뒤 이전 입력이 남음 | resetPositions의 Object.assign은 기존 임시 속성을 제거하지 않음 | pointer·더블탭·태클·수동 이동·액션 만료값을 명시적으로 초기화 |
| 마지막 터치 정보 누락 | 수신자 획득 485~491은 game.lastTouch 갱신 없음 | 소유권 획득의 공통 처리에서 lastTouch 및 재개 타이머 갱신 |

## 5. 확정할 조작 규칙

| 상황 | 어린이 행동 | 게임 동작 |
|---|---|---|
| 우리 공 | 아무 빈 곳에서 누르고 원하는 방향으로 끌어 유지 | 계속 드리블. 손가락을 멈춰도 선수는 계속 이동 |
| 우리 공 | 동료 방향으로 끌다가 놓음 | 청록색으로 표시된 동료에게 패스 |
| 우리 공, 상대 골대 근처 | 상대 골대 방향으로 끌다가 놓음 | 주황색으로 표시된 골문으로 슛 |
| 우리 공 | 손가락을 처음 누른 곳 근처로 되돌려 놓음 | 킥 취소, 공 유지 |
| 상대 공 | 끌어 유지 | 선택된 수비수 이동/추격 |
| 상대 공 | 상대 근처 두 번 탭 또는 태클 버튼 | 가까운 필드 선수가 압박하고 접촉 시 탈취 |
| 탈취 직후 | 수비 때 누른 손가락을 놓음 | 공 유지. 다음 터치부터 드리블·패스·슛 가능 |
| GK 소유/골킥 | 기다림 또는 패스 방향 지정 | 1초 준비 후 자동 배급. 유효한 지정이 있으면 그 방향 활용 |

이동 중에는 킥하지 않는다. 오래 누르고 있어도 놓으면 실행되며 속도 판정 때문에 패스가 취소되지 않는다. 정지하고 싶다면 시작점 근처로 돌아와 놓는 방법을 튜토리얼에 그림과 짧은 문장으로 알려준다.

## 6. 구현 단계

### P1 — 연속 이동, 경계, 입력 초기화

- 최신 브랜치의 매 프레임 상대 이동 목표 방식은 유지한다. pointermove 이벤트 횟수에 이동이 종속되지 않게 한다.
- 필드 선수의 기준 경계는 `x=-33..33, y=1..104`로 모은다. 경기장 밖 이동을 허용하는 변경이 아니다. 상하 공격 방향 모두 동일한 범위를 쓴다.
- 방향 전환 시 이전 목표점에 끌려가지 않고 현재 방향으로 바로 움직인다. 공을 가진 선수와 수비수가 같은 조작 원칙을 따른다.
- 경기 시작·재시작·득점 킥오프·하프타임에서 입력, double-tap, manualUntil, tackleUntil, 액션 시간, 재개 상태를 정리한다. Object.assign만으로 초기화가 된다고 가정하지 않는다.
- `pointercancel`/`lostpointercapture`/탭 전환은 킥을 발생시키지 않는다. 캡처 해제 시 자신의 이벤트를 중복 처리하지 않게 한다.
- 터치 시작 시 공격/수비 상황과 소유권 세대를 기록한다. 소유권이 바뀌면 해당 공격 입력을 취소한다. 수비 도중 탈취도 이전 입력의 킥을 취소한다.
- 소유권 획득 helper 하나를 수신·수동/자동 태클·GK 포구 경로에서 재사용한다. 소유자, 공 속도/위치, lastTouch, 입력 무효화, GK 시간 기록이 서로 다른 경로에서 빠지지 않게 한다. 물리엔진 전면 재구성은 하지 않는다.

### P2 — 손을 놓는 위치와 방향에 맞는 패스/슛

- `resolveGesture`를 안내선과 실제 킥의 공통 판정으로 유지한다. 현재 선수 좌표, 화면상 손끝, 최초 터치점, 현재 상대 골문을 입력으로 사용한다.
- 원시 손가락 시작점은 흰 점선용으로 보존한다. 화면 좌표와 월드 좌표를 혼용하지 않는다. 방향 변환은 현재 project/unproject와 맞추되 카메라 이동을 사용자 드래그로 더하지 않는다.
- 매 프레임 선수와 카메라 이동 후 aim을 갱신한다. pointerup에서 마지막 실제 좌표로 같은 함수를 한 번 더 호출하고 한 번만 kick한다.
- 초기 판정 순서:
  1. 터치 취소·소유권 변경·재개 대기이면 일반 킥 차단.
  2. 시작점 주변 취소 영역 안이면 공 유지.
  3. 손끝 가까이에 유효한 우리 동료가 있으면 패스. 자기 자신 제외, 거리 50 이내, 드래그와 반대 방향의 동료는 제외.
  4. 명확한 동료 지정이 없고 슈팅 구역 안에서 상대 골대 방향을 가리키면 슛.
  5. 그 외에는 기존 passTargetFor 방향 보정으로 패스. 후보가 없으면 해당 방향으로 실제 공을 찬다.
- 초기 조정값: 취소 영역 `clamp(width*.035,12,16)` CSS px, 손끝 동료 탐색 반경 32 CSS px, 슈팅 구역 상대 골라인까지 35 월드 단위. 이 값은 출발점이며 아래 재현 결과로 조정한다.
- 슛은 빠른 속도나 큰 손가락 이동을 필수로 요구하지 않는다. 유효한 드래그와 골문 방향으로 판단하고 길이는 힘 조절에 사용한다. 먼 후방의 골대 방향 드래그는 패스가 기본이다.
- 방향 패스의 기존 넓은 후보 선택을 무조건 더 넓히지 않는다. 손끝 후보 우선 순위를 넣은 뒤 오선택 재현이 남는 경우에만 각도를 조정한다.
- 흰 점선: 실제 손가락 궤적. 청록선+동료 링: 패스. 주황선: 골문까지. 취소 영역: 색선 제거. 태클은 이 선과 다른 짧은 수비 표시를 사용한다.
- 손가락을 고정한 동안 동료가 움직이거나 카메라가 따라가도 선의 시작점·목표는 최신 위치여야 한다. 같은 프레임 상태에서 표시된 대상과 실제 킥 대상은 같아야 한다.

### P3 — 도달 가능한 태클과 수비 보조

- 버튼과 더블탭은 동일한 tryManualTackle 경로를 호출한다. 수비 드래그 해제 자체를 또 다른 태클 명령으로 추가하지 않는다.
- 필드 선수 중 가장 가까운 선수를 선택하고 선택 링을 표시한다. GK는 일반 추격·압박·태클 후보에서 제외한다.
- 성공 반경은 실제 접촉 기준 2.8 월드 단위 하나로 통일한다. 5.2 거리에서 공 소유자를 즉시 바꾸는 기존 처리를 없앤다.
- 접촉 전에는 자동 압박한다. 현재 0.75초 대신 최대 2.5초를 초기값으로 사용하며 매 프레임 상대의 현재 위치를 향한다. 상대가 멀어지면 실패할 수 있다.
- 소유권 변경, 경기 재개/종료, 다른 선수를 직접 조작하면 기존 압박을 종료한다. 활성 압박 중 연타로 시간이나 속도를 무한 연장하지 않는다.
- 성공 시 실제 공 위치를 탈취 선수에 맞추고 기존 효과음/짧은 피드백을 사용한다. 공격 제스처는 새 터치부터 시작한다.
- 성공 후 기존 0.75초 재사용 제한과 짧은 재탈취 보호를 일관되게 적용한다. 실패·접근 중 상태도 표시하여 버튼이 무반응으로 보이지 않게 한다.
- AI는 기존 '가까운 한 명 압박 + 다음 한 명 진로 커버'를 유지한다. GK 제외와 수동 조작 우선순위만 수정한다. 국가 능력치나 상대 전체 속도를 재조정하지 않는다.

### P4 — 골키퍼 배급·골킥은 1초 후 재개

소규모 재개 상태 하나를 둔다: `game.restart = null | {kind, side, taker, readyAt, queuedTarget}`. 별도 게임 상태 관리 라이브러리는 필요 없다.

- GK가 실제로 공을 획득한 순간 `kind='keeper', readyAt=game.elapsed+1.0`을 한 번 기록한다. 매 프레임 1초를 다시 더하지 않는다.
- 골대 바깥으로 공이 골라인을 통과하면 반사를 제거하고 수비팀 GK의 골킥 위치를 준비한다. 위치를 준비한 시점에 `kind='goalKick', readyAt=game.elapsed+1.0`을 기록한다.
- **이번 아케이드 범위의 제안:** 골대 바깥 골라인 아웃은 모두 수비팀 골킥으로 단순화한다. 정식 코너킥은 별도 범위이며 구현한 것으로 보고하지 않는다. 이 단순화를 README에 명시한다.
- 대기 중 공은 GK/골킥 위치에 고정한다. 일반 공 줍기·상대 태클·GK 자유 드리블·골 판정이 해당 공에 적용되지 않게 재개 분기를 일반 처리보다 먼저 실행한다.
- 짧은 원형 준비 표시나 '공을 줄게!' 안내를 사용한다. 긴 전체 화면 메시지는 쓰지 않는다.
- 홈 GK에 대해 사용자가 대기 중 패스 방향을 놓으면 선택을 저장한다. 1초 이전에 발사하지 않으며, 손가락을 계속 누르고 있어도 타이머를 무기한 연장하지 않는다.
- 1초 시점에는 지정한 동료가 여전히 유효하면 그 동료, 아니면 기존 bestAiPass/laneRisk를 활용해 필드 동료에게 패스한다. 후보가 없으면 필드 안쪽의 안전한 방향으로 배급한다. 새 AI 계획기는 만들지 않는다.
- 상대 GK도 동일한 1초 재개 규칙을 따른다.
- 재개 상태를 먼저 해제하고 kick을 한 번 호출한다. 기존 공 속도·마찰·수신 처리와 lastKicker 잠금을 사용한다. 공을 동료에게 순간이동시키지 않는다.
- pause에서는 남은 시간이 멈춘다. resume에서 남은 활성 게임 시간을 이어간다. 하프타임·득점·재시작에서는 대기 중 재개/선택을 제거한다.
- GK 정상 포구의 공 소유 상태와 골킥의 위치 준비를 구분하되, 배급 타이머/수신자 선택은 공유한다.

## 7. 모바일 화면 조정

- 플레이 기준: 360×800, 390×844, 412×915. CSS px 기준으로 터치 반경을 정의하고 DPR을 중복 곱하지 않는다.
- 하단 도움말은 `끌기 → 이동 · 놓기 → 패스/슛`처럼 한 줄로 줄인다. 도움말과 장식은 pointer-events:none을 사용하여 드래그 시작을 가로막지 않게 한다.
- 태클 버튼은 오른쪽 엄지 위치에 유지하되 도움말/safe area와 겹치지 않게 한다. 드래그 중 두 번째 손가락으로 눌렀을 때의 취소/소유권 변경도 검증한다.
- 좌측에 작은 `공격 ↑ / 우리 골대 ↓` 표시를 두고 후반에 뒤집는다. 터치를 가로채지 않는다.
- 월드 경계를 축소해서 하단 HUD 가림을 해결하지 않는다. 우선 비대화형 도움말의 겹침을 줄인다. 필요하면 project/unproject가 공유하는 화면상 위/아래 여백만 같이 조정하고 round-trip 테스트를 추가한다.
- 공 소유 상실 후 선택 선수가 화면 밖에 남는 경우, 활성 수동 조작 중 카메라 추적 대상을 선택 선수로 바꾸는 작은 보정을 검토한다. 기본 원근과 월드 좌표계를 재설계하지 않는다.
- 입력은 Canvas와 Pointer Events를 유지한다. pointer capture가 있어도 OS가 터치를 취소할 수 있으므로 취소 시 조용히 멈추고 공을 차지 않는 것이 정상 동작이다.

## 9. 완료 판정용 테스트

### 로직

1. 각 viewport, 전후반, 상하좌우에서 한 번 드래그 후 pointermove 없이 5초 이동. 필드 안의 14단위 지점에서 멈추지 않음. 대각선 속도가 직선보다 빨라지지 않음.
2. 경계 바로 안쪽에서 네 방향 이동과 반대 방향 전환. 위치가 경계 밖으로 넘어가지 않고 안쪽으로 다시 이동 가능.
3. 짧은/대각선/긴 패스 각 20회, 전후반 슛 각 20회. 0.1초·1초·3초 길이로 누른 뒤 동일 방향 놓기. 속도 때문에 액션이 취소되지 않음.
4. 동료가 골대와 같은 방향에 있을 때 손끝으로 지정하면 패스. 후방에서 골대 방향을 가리키면 패스. 슈팅 구역의 골문 방향은 슛. 취소 영역은 킥 없음.
5. 손가락 고정 중 60프레임 이동/동료 이동 후 안내 시작점과 목표가 현재 좌표와 일치. pointerup 시 같은 판정에서 같은 대상으로 한 번 킥.
6. 우리 공→상대 공→다시 우리 공, 수비 드래그→태클 성공→손 떼기. 이전 입력이 공을 새로 차지 않음.
7. 접촉 태클 성공, 12단위에서 정지 상대 추격 후 성공, 멀리 도망가는 상대는 순간 탈취 안 됨. 10회/초 연타로 중복 소유 변경·속도 누적 없음. GK 선택 안 됨.
8. 두 팀 GK 각각 포구 후 0.99초에는 소유, 1.0초 이상 첫 프레임에 한 번 kick. 30/60fps에서 배급 시점은 1초+한 프레임 이내.
9. 상·하 골라인, 두 팀, 전후반에서 골킥 준비 후 동일 시간 검증. 골문 안 통과는 정상 득점이며 골킥으로 바뀌지 않음.
10. 재개 0.4초 후 pause, 임의의 대기 뒤 resume, 활성 시간 약 0.6초 후 배급. 유효한 동료 없음·선택 동료 이동/무효화 때도 1초 재개가 끝남.
11. 1초 만료와 사용자 pointerup이 같은 프레임에 발생해도 한 번 kick. 재개 대기 중 수비 태클은 공 탈취 불가.
12. 득점·하프타임·retry·메뉴 복귀·새 경기에서 pointer/태클/재개가 남지 않음. pointercancel/lostpointercapture/visibilitychange 후 유령 킥 없음.

테스트는 양쪽 GK의 실제 공 획득 경로도 거쳐야 한다. 테스트에서 ball.owner만 바꾸고 타이머를 수동으로 넣어 기능이 통과한 것처럼 만들지 않는다. 기존 테스트의 소유권 설정은 새 공통 helper와 일관되게 수정한다.

### 브라우저·실기기

- 세 viewport에서 실제 누르기→이동→고정→놓기 시퀀스, 화면 가장자리 시작, 하단 HUD 근처, 태클 버튼과 동시 입력을 확인한다.
