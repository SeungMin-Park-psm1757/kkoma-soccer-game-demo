# 모바일 조작·수비 설계 — Luna 구현용

작성일: 2026-10-02. 분석 기준: `origin/main`의 `4d8f5db3c1e2dc3abeafa5d29b417f914eb897a6`.

목표는 7세 어린이가 한 손가락으로 이동·패스·슛·태클을 하고, 전후반 모두 공격 방향을 알아보는 것이다. 이 문서는 구현 설계이며 게임 코드는 변경하지 않았다. 최신 main을 다시 fetch한 뒤 이 문서와 코드의 차이를 확인하고 새 기능 브랜치에서 구현한다.

## 1. 코드에서 확인한 문제

| 문제 | 현재 코드와 확인 결과 | 변경 방향 |
|---|---|---|
| 오래 끌어도 이동이 멈춤 | `pointermove`가 시작 위치 기준 목표점만 설정하고 이동량을 월드 거리 14로 제한한다. y=70에서 아래로 400px 끌고 4초 유지하면 targetY=84, 실제 y≈83.84에서 정지한다. | 손가락 변위를 이동 방향·속도로 사용하고 매 업데이트마다 목표점을 갱신한다. |
| 드리블 후 손을 떼면 정지 | 홈팀 공 소유자의 느린 드래그 종료에는 추가 이동 명령이 없다. | 공격 이동은 손을 떼면 정지하는 것으로 명확히 정의한다. 계속 이동은 누르는 동안 지속한다. |
| 태클을 의도적으로 할 수 없음 | `finishPointer`에는 패스·슛·이동만 있다. `updateMatch`의 d<1.55 근접 확률 처리만 공을 탈취한다. | 수비 스와이프와 수동 태클 판정을 추가한다. |
| 수비수가 잘 바뀌고 골키퍼가 선택될 수 있음 | `chooseControlledPlayer`, `nearestPlayers`에 GK 제외 조건이 없다. GK는 별도 이동 분기에서 처리되므로 압박 선수 슬롯에 GK가 포함되면 필드 압박이 줄 수 있다. | 수비 자동 선택·압박 역할에 필드 선수만 포함한다. |
| 긴 드래그의 최종 판정이 불안정할 수 있음 | `gestureMetrics`는 시작부터 전체 경과 시간으로 속도를 계산한다. 빠르게 끌고 잠깐 머물면 release 판정이 이동으로 바뀐다. | 최근 이동 속도와 마지막 유효 preview를 제한된 시간 동안 사용한다. |
| 끝부분 이동 범위가 일관되지 않음 | 드래그 중 y=3..102, 다른 이동 명령 y=1..104. 실제 경기장 y=0..105. | 필드 선수 이동 범위를 x=-33..33, y=1..104로 공유한다. |
| 작은 모바일 화면에서 읽을 정보가 많음 | 하단에 조작 문장이 계속 표시되고 공격 방향 표시는 없다. `hint`와 `drag-hint`에는 pointer-events 제외가 없다. | 짧은 상황별 안내·방향 아이콘을 사용하고 안내가 터치를 가로막지 않게 한다. |

기존 `node tests/mobile-logic.mjs`와 `node --check game.js`는 분석 시 통과했다. 위 재현은 기존 테스트의 가상 경기 환경으로 확인했으며 실기기 재현은 아직 하지 않았다.

## 2. 한 손가락 조작 규칙

별도 이동·패스·슛·태클 버튼은 추가하지 않는다. 1차 구현은 드래그 하나로 동작한다.

| 경기 상황 | 손가락 행동 | 결과 | 안내 |
|---|---|---|---|
| 우리 팀이 공 소유 | 누르고 천천히 끌어 유지 | 공 소유자가 해당 방향으로 계속 드리블 | 작은 이동 원, 흰 점선·손가락 포인터 |
| 우리 팀이 공 소유 | 동료 쪽으로 짧고 빠르게 끌고 떼기 | 기존 자동 보정 패스 | 청록 목표선·동료 링 |
| 우리 팀이 공 소유 | 공격 골문 쪽으로 길고 빠르게 끌고 떼기 | 기존 슛 | 주황 골문선 |
| 상대 팀이 공 소유 | 손을 대지 않음 | 자동 선택된 주 수비수가 상대를 추적 | 선택 마커·수비 방향 표시 |
| 상대 팀이 공 소유 | 누르고 끌어 유지 | 선택된 수비수의 이동을 직접 조절 | 이동 원·흰 점선 |
| 상대 팀이 공 소유 | 공 소유 상대 쪽으로 빠르게 끌고 떼기 | 가까운 상대에게 보정된 태클 1회 | 보라색 목표선·태클 가능 링 |
| 상대 팀이 공 소유 | 우리 필드 선수 짧게 탭 | 해당 선수 선택 | 선택 마커 이동 |
| 공이 자유롭게 움직임 | 누르고 끌기 또는 손을 떼고 관찰 | 직접 이동 또는 가까운 필드 선수의 자동 회수 | 패스·슛·태클 preview 없음 |

수비 중 일반 이동 드래그를 놓으면 선택 선수는 자동 추적으로 복귀한다. 공격 중 이동 드래그를 놓으면 공 소유자는 멈춘다. 태클은 공격 입력과 경기 상황으로 구별하므로 복잡한 모드 버튼을 배우지 않아도 된다.

더블탭 태클은 1차 구현에 넣지 않는다. 이 설계의 드래그 태클로 실기기 테스트한 뒤 필요할 때 보조 조작으로 추가한다.

### 입력 판정의 우선순위

1. `pointercancel`, `lostpointercapture`, 일시정지·탭 전환·득점·하프타임이면 입력을 취소한다. 패스·슛·태클을 실행하지 않는다.
2. 터치 시작 때 공 소유 상황과 조작 선수를 기록한다. 드래그 중 소유 팀이나 조작 선수의 공 소유 여부가 바뀌면 예약한 동작을 무효화한다. 이동은 유지할 수 있지만 같은 release를 탈취 직후 패스로 다시 해석하지 않는다.
3. 손가락 변위가 dead zone 안이면 이동하지 않는다. 수비에서 움직임 없는 짧은 탭만 선수 선택으로 처리한다.
4. 손가락을 유지하면 지속 이동한다. 빠른 동작 preview가 잠깐 나타나더라도 hold 이후에는 이동으로 복귀한다.
5. 빠른 swipe의 유효 preview가 남아 있는 release만 공격 동작 또는 태클로 처리한다. release에서 목표와 소유 상황을 다시 검증한다.

추천 시작값은 조정 가능한 소수의 상수로 둔다. 기존 공격 거리 기준 .035/.16 및 속도 기준 .55/.7을 초기 기준으로 유지한다. 속도는 최근 80~120ms의 이동 표본으로 계산하고, 마지막 유효 preview는 최대 140ms까지만 유지한다. 마지막 이동 후 약 180ms 이상 유지하면 예약 동작을 해제한다. 이 값은 제안이며, 기존 공격 100회 회귀 테스트와 실기기 테스트로 확정한다. 샘플 수가 부족하면 기존 전체 이동 속도를 사용한다.

손가락은 하나만 처리한다. 두 번째 포인터는 무시하며 `setPointerCapture`로 화면 가장자리 release를 받는다. 브라우저 `dblclick` 이벤트에는 의존하지 않는다.

## 3. 지속 이동과 아래쪽 정지 문제 수정

`pointer.start`는 점선과 제스처 거리의 기준으로 유지한다. 이동에는 별도의 방향 입력을 사용한다.

- 이동 dead zone은 약 6~8 CSS px, 최대 이동 입력 반경은 약 40~48 CSS px로 시작한다. 실제 viewport 폭에 맞춰 제한된 비율로 조정한다.
- 원점에서 손가락으로 향하는 단위 벡터와 dead zone 이후 크기(0..1)를 계산한다. 세로·가로 월드 변환은 현재 projection 스케일을 사용한다.
- `updateMatch`에서 현재 선수 위치를 기준으로 짧은 앞쪽 목표점을 계속 갱신하고 기존 `moveToward`를 호출한다. 기존 manual 이동 속도 배율을 초기값으로 사용한다.
- 손가락을 고정해도 목표점이 선수와 함께 움직이므로 14 거리 도착 후 멈추지 않는다. 손가락을 원점으로 되돌리면 정지한다.
- 실제 필드 경계에 도착한 때만 정지한다. 경계 방향 성분을 제한하고 남은 성분으로 터치라인을 따라 이동할 수 있어야 한다.
- 빠른 패스·슛·태클 preview 중에는 이동을 일시 보류하여 조준 때문에 선수가 먼저 크게 움직이지 않게 한다. hold로 이동 판정이 되면 이동을 다시 적용한다.

`CAMERA_SPAN`, `cameraStart`, 공 추적 카메라 보간은 유지한다. 화면 밖으로 움직이거나 다른 선수의 공 소유로 카메라가 이동하면 입력은 월드 위치가 아니라 방향 기준으로 계속 동작한다.

## 4. 수동 태클 규칙

첫 버전은 짧게 발을 뻗는 스탠딩 태클로 한다. 슬라이딩·카드·부상·파울 규칙은 추가하지 않는다.

| 항목 | 초기 제안 |
|---|---|
| 발동 | 상대가 공을 소유하고, 사용자가 상대 쪽으로 빠르게 swipe 후 release |
| 방향 보정 | 입력 방향 ±60° 안의 상대 공 소유자에게 보정. 반대 방향 swipe는 보정하지 않음 |
| 시작 가능 거리 | 월드 거리 약 5.5 이내. 그 밖에서는 태클 preview를 표시하지 않음 |
| 전진 | 약 0.16초 동안 최대 2.5 월드 거리. 필드 경계를 지킴 |
| 성공 | 태클 이동 선분이 실제 공의 위치에 약 1.8 월드 거리 이내로 접근한 경우 |
| 실패 | 공이 이동해 reach 밖에 있거나, 상대가 이미 패스·슛했거나, 방향이 맞지 않는 경우 |
| 반복 제한 | 선수별 약 0.8초 cooldown, 실패 후 약 0.22초 회복 |
| 탈취 직후 | 약 0.35초 동안 자동 접촉 탈취를 보호하여 즉시 재탈취되는 현상을 방지 |

위 수치는 확정 밸런스가 아니라 초기값이다. 사용자의 유효 태클 성공 여부는 거리·방향·공 위치로 결정하고 추가 랜덤 실패 확률을 넣지 않는다. 선수·공의 `x/y`를 순간적으로 끌어오는 자석 판정도 사용하지 않는다.

각 업데이트에서 태클의 이전 위치→현재 위치 선분과 공 사이의 최단 거리를 검사하여 30/60fps의 결과 차이를 줄인다. 움직이는 공은 태클 전진 동안 매 프레임 현재 위치로 검사한다. 성공하면 기존 공 회수 절차처럼 owner·속도·lastTouch·controlled를 갱신하고 오래된 aim/입력 예약을 비운다.

기존 자동 근접 탈취의 시도 확률·난이도 계수는 1차에서 유지한다. 공 소유권 보호 시간과 수동 태클 회복 중에는 자동 탈취가 개입하지 않도록 한다. 수동 태클을 완성하는 과정에서 상대 전체 난이도를 재조정하지 않는다.

## 5. 수비 AI와 선수 선택

### 선택 유지

- 상대가 공을 얻으면 공에 접근하기 좋은 필드 수비수를 자동 선택한다. 골키퍼는 자동 선택에서 제외한다.
- 사용자가 직접 탭했거나 드래그하는 선수는 AI가 임의로 다른 선수로 바꾸지 않는다.
- 자동 선택은 매 프레임 바꾸지 않는다. 약 0.25초 간격으로 검토하고 후보가 기존 선수보다 접근 예상 시간이 약 20% 이상 유리할 때 교체한다.
- 접근 시간은 선수와 짧은 예상 공 소유자 위치 사이의 거리/실제 이동 속도로 계산한다. 우리 골문과 상대 사이에 있는 후보를 소폭 우선한다. 소유자의 최근 이동량을 추정하되 예상 지점은 약 0.25초까지만 앞서 본다.
- 상대 패스·공 회수·골·전후반 전환 때 선택을 재평가한다. 수동 입력 중에는 새 선수를 강제로 지정하지 않는다.

### 주 수비·커버·대형 유지

수비 역할은 기존 두 명 추적 구조를 활용한다. 필드 후보 목록과 역할을 팀별 업데이트에서 한 번 계산하여 선수 루프에 공유한다.

1. **주 수비 1명**: 상대의 짧은 예상 이동 위치를 향해 접근한다. 직접 조작이 없을 때 선택된 선수도 이 행동을 한다. 수동 이동·태클·회복이 시작되면 그 명령이 우선한다.
2. **커버 1명**: 상대와 우리 골문 사이 약 6~8 거리를 유지하여 돌파를 막는다. 주 수비가 태클을 실패해도 모두 공에 달려들지 않는다. 커버 지점은 필드 안에 제한한다.
3. **나머지 필드 선수**: 기존 homeX/homeY 기반 대형을 유지하며 공 방향으로 조금 이동한다. GK는 현재 골문 방어 분기를 유지한다.

기존 `nearestPlayers`를 수비 경로에서 사용할 때 GK를 제외한다. 패스 대상·실제 공 회수에 사용되는 다른 nearest 함수의 의미를 일괄 변경하지 않는다. 국가 능력치 및 difficulty 데이터는 유지한다.

공이 자유로운 상황에서는 팀당 필드 선수 1명이 우선 회수한다. 사용자가 움직이는 선수와 AI 회수 선수가 불필요하게 겹치지 않도록 수동 선수 우선권을 적용한다.

## 6. 휴대폰 화면 안내

- 기존 흰 점선·손가락 원·청록 패스선·주황 슛선을 유지한다. 수비에서 유효 태클을 조준하면 보라색 선과 상대 주위 링으로 바뀐다. 가능 범위를 벗어나면 이동 안내로 즉시 복귀한다.
- 왼쪽 가장자리에 폭 약 24~28px의 가벼운 방향 표시를 둔다. 골문/공 아이콘의 화살표는 항상 **우리 공격 골문**을 가리키고, 방패 아이콘 화살표는 **우리 골문**을 가리킨다. 소유 상황에 따라 해당 아이콘만 조금 강조한다.
- 화살표는 `attackGoal(0)`와 `ownGoal(0)`에서 계산한다. 전반 ↑공격/↓수비, 후반 ↓공격/↑수비로 바뀐다. 하프타임 때 약 1초간 강조하고 기존 안내를 사용한다. 공격 방향과 현재 공 소유 상황을 혼동하지 않게 한다.
- 화면 하단 상시 긴 문장은 경기 시작 약 3초 뒤 줄인다. 공격에는 `끌어서 이동 · 빠르게 떼면 패스/슛`, 수비에는 `상대 쪽으로 빠르게 떼면 태클`을 짧게 보여주고 이후 필요할 때 표시한다.
- `.hint`, `.drag-hint`, 방향 안내는 `pointer-events:none`으로 입력을 통과시킨다.
- 메뉴·일시정지의 터치 영역은 최소 44×44 CSS px로 확보한다. 선수 선택은 최소 약 24px 반경의 화면 터치 영역을 사용하며 물리 hitbox를 바꾸지 않는다.
- safe area와 선수 발이 잘리는 문제는 `resize`에서 공유 화면 영역을 계산해 처리한다. HUD 아래를 pitch top, 하단 safe area와 약 20~24px 발 여유를 제외한 위치를 pitch bottom으로 사용한다. `project`, `unproject`, `worldPerPixelY`가 동일한 top/bottom을 사용해야 한다. 카메라 월드 알고리즘은 유지한다.
- 태클 전용 그림이 없어도 기존 선수 자산과 짧은 기울기·이동 잔상·링 효과로 동작을 알린다. 자산 미로드 때 Canvas fallback을 유지하고 이미지에 공을 추가하지 않는다.

## 7. Luna의 구현 순서와 수정 위치

1. `game.js`: `pointermove`·`gestureMetrics`·`finishPointer`·`updateMatch`의 수동 이동 분기를 정리하여 지속 드래그 이동을 구현한다. 먼저 14 거리 정지 재현을 해소한다.
2. `game.js`: 수동 태클 시작·업데이트·공 회수·cooldown·소유권 보호를 추가한다. 입력 취소와 소유권 전환을 먼저 연결한다.
3. `game.js`: `chooseControlledPlayer`와 수비 후보 계산에 GK 제외·선택 유지·주 수비/커버 역할을 적용한다.
4. `game.js`/`game.css`/필요 시 `index.html`: `drawAim`·`drawPlayer`에 수비 피드백을 연결하고 방향 화살표·짧은 모바일 안내·터치 통과·공유 viewport 여백을 반영한다.
5. `tests/mobile-logic.mjs`: 아래 검증을 추가한다. 새 테스트 프레임워크·런타임 의존성을 추가하지 않는다.

국가 데이터·유니폼·manifest·패스 대상 보정·킥의 공 속도·득점·월드컵 저장·기존 스프라이트를 변경하지 않는다. 입력 개선 때문에 공격 판정 임계값 변경이 필요하면 실패 사례로 근거를 남기고 가장 좁은 조정만 한다.

## 8. 완료 검증

### 기존 회귀

`node tests/mobile-logic.mjs`, `node --check game.js`, `git diff --check` 통과. 기존 짧은/대각/긴 패스 각 20회와 전후반 슛 각 20회, 국가·kit·저장·스프라이트 fallback 검증을 유지한다.

### 추가 로직 테스트

- 360×800 및 412×915 입력 환경에서 위/아래/좌/우로 4초 유지. 14 거리 이후 계속 움직이며 실제 필드 끝에서만 멈춘다. 손가락을 원점으로 복귀하면 정지한다.
- 전후반 각각 y=5..100을 충분히 이동 가능. y=1..104, x=-33..33 밖으로 나가지 않는다. 모서리에서 한 방향이 막혀도 다른 방향 이동은 가능하다.
- 태클 가능한 거리/방향의 정지 상대 20회 성공. 먼 상대·반대 방향·회복/cooldown 중 입력은 탈취하지 않는다. 움직이는 상대는 실제 공 접촉 여부와 일치한다.
- 태클 전에 상대가 패스하면 먼 공이 자동 탈취되지 않는다. 탈취 직후 동일 release로 패스/슛이 실행되지 않고 자동 재탈취가 보호된다.
- 30/60/120fps에서 동일 이동·태클 시나리오를 검사한다. 태클과 공이 접촉 구간을 건너뛰어 프레임 속도별 결과가 달라지지 않는다.
- 수비 자동 선택은 GK를 선택하지 않는다. 손가락으로 조작 중인 선수를 바꾸지 않고, 근접 후보가 오갈 때 마커가 매 프레임 바뀌지 않는다.
- 수비 역할은 주 수비·커버 각 1명이며 나머지는 대형을 유지한다. 빈 공 회수와 패스에 따른 타깃 전환도 확인한다.
- `pointercancel`, `lostpointercapture`, 두 번째 손가락, pause/resume, 탭 전환, goal/halftime 입력 취소에서 태클·패스·슛이 실행되지 않는다.
- 전반/후반 방향 화살표가 득점 판정의 `attackGoal(0)`와 동일한 방향을 가리킨다. 소유권 전환만으로 화살표가 뒤집히지 않는다.

### 브라우저·실기기

브라우저에서 두 viewport의 공격 이동·패스·슛·수비 추적·태클 성공/실패·pause/resume를 직접 실행한다. HUD/하단 안내/손가락 아래에서 터치가 가려지지 않고 골문 근처 선수의 발이 잘리지 않는지 화면으로 확인한다. Galaxy Android 실기기에서 주소창·safe area·한 손가락 조작과 30fps 이상을 별도로 확인한다. 실기기 미실행은 완료 보고에 명시한다.

검증 후 기능 단위로 커밋·푸시하고 main 대상 Draft PR을 생성한다. 직접 main 병합·배포는 하지 않는다. 최신 main 기준 브랜치·SHA·변경 파일·검증·남은 실기기 항목을 보고한다.

## Luna에 전달할 첫 메시지

> 최신 main을 fetch하고 `docs/MOBILE_DEFENSE_DESIGN.md`를 기준으로 모바일 지속 드래그 이동, 수동 태클, 수비 추적·선수 선택, 공격/수비 방향 화살표를 순서대로 구현해줘. 문서의 수치는 초기 제안이며 기존 공격 회귀 테스트와 실제 실패 사례를 근거로 확정해줘. 새 기능 브랜치를 만들고 기존 국가·kit·월드컵·스프라이트·득점/패스/슛 물리를 유지해줘. 문서의 추가 검증과 모바일 두 viewport 확인 후 커밋·푸시·Draft PR까지 진행하고 main에는 직접 merge하지 마.
