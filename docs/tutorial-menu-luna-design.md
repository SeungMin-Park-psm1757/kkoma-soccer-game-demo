# 튜토리얼 메뉴 및 직접 조작 연습 — Luna 구현 설계

작성: 2026-10-03. 저장소: `SeungMin-Park-psm1757/kkoma-soccer-game-demo`.
분석 기준: `chatgpt/kid-tutorial-tackle`, `1c733f5a4fd66cce2b959c370b8527a9a4b68600`.
상태: **P1~P4 구현 및 검증 완료**. 구현은 `chatgpt/kid-tutorial-tackle`에서 기존 PR #5를 이어 진행했다.

## 1. 목표와 선택한 범위

7세 어린이가 긴 설명을 읽지 않고 손가락을 직접 움직여 이동·패스·슛·태클을 익힌다. 이번 구현은 튜토리얼 메뉴와 네 가지 연습에 집중한다.

- 현재 네 장의 설명 카드를 `조작 연습` 메뉴와 플레이 가능한 연습으로 교체한다.
- 모든 연습은 실제 경기의 입력·공 물리·포구·태클 판정을 사용한다.
- 혼자 연습할 수 있도록 등장 인원과 상대 행동만 제한한다.
- 한 번 성공하면 해당 연습을 완료한다. 시간 제한·패배·별점·속도 점수는 없다.
- 골키퍼·골킥 별도 연습, 음성 안내, 신규 그림, 신규 효과음은 이번 범위에 포함하지 않는다.
- 국가 능력치, kit, AI 난이도, 실제 경기 조작 임계값, 카메라 투영, 월드컵 구조는 현재 값을 유지한다.

선택 이유: 설명 카드만 다듬는 방법은 구현량이 작지만 손을 떼는 패스/슛과 두 번 탭하는 태클을 실제로 익혔는지 확인할 수 없다. 네 개의 짧은 실제 연습을 채택한다.

## 2. 현재 코드에서 확인한 사실

| 경로 | 현재 동작 | 구현 시 주의 |
|---|---|---|
| `showHome`, `tutorialPages`, `showTutorial` | 첫 실행 안내 및 네 개 설명 카드 | 시작 버튼과 다시 보기 경로를 새 메뉴로 연결 |
| `kkoma-tutorial-done` | 완료와 건너뛰기 모두 true | 기존 값은 안내를 본/넘긴 여부로 유지. 숙련도 증명으로 사용하지 않음 |
| `screen` / `.screen` | 전체 화면 overlay, z-index 3 | 연습 중 안내를 이 요소에 넣으면 Canvas 터치가 막힘 |
| `startMatch` | 경기 상태 생성, 22명 생성, 경기 음악 선택 | 연습은 메뉴 음악 유지, mode와 월드컵 값을 덮어쓰지 않음 |
| `updateMatch` | 경기 시계, AI, 이동, 포구, 득점 처리 | 연습에서도 kick/포구 타이머용 elapsed는 진행. 75/150초 종료와 일반 AI만 연습 조건으로 제한 |
| `pointerdown`, `tryManualTackle` | `appScreen === 'match'`에서만 실행 | 연습 플레이도 match 화면 상태로 두고 game 안의 연습 표시로 구분 |
| `resolveGesture`, `refreshPointerAim`, `finishPointer` | 끄는 동안 이동, 놓으면 표시된 패스/슛 | 별도의 연습용 입력 판정을 만들지 않음 |
| `setPossession` | 포인터 및 소유권/태클 상태 정리 | 공을 받은 뒤 ball.lastKicker가 지워지므로 성공 근거는 별도로 기록 |
| `completeManualTackle` | 실제 접촉 반경에서 소유권 변경 | 소유권 변화만으로 태클 성공을 인정하면 자동 수비도 통과할 수 있음 |
| `pauseGame`, resume, visibilitychange | 입력 초기화, 시계·음악 정지/복귀 | 연습 화면과 메뉴 음악도 같은 생명주기로 처리 |

현재 프로젝트에 `docs/ai/GAME_SPEC.md`는 없다. 이 문서의 구현 대상은 위 실제 코드 경로이며, 새 게임 엔진이나 프로젝트 전체 명세를 만들 필요는 없다.

## 3. 메뉴와 흐름

홈의 튜토리얼 버튼 이름은 항상 `👆 조작 연습`으로 통일한다. 연습을 이미 마쳤어도 같은 자리에서 들어간다.

```text
               조작 연습
       손가락으로 직접 해봐요

       [ 👆 이동 ] [ 🤝 패스 ]
       [ 🥅 슛   ] [ 🛡 태클 ]

           [ 처음부터 연습 ]
           [ 바로 경기하기 ]
           [ 메뉴로 ]
```

- 네 타일은 2×2, 아이콘과 2~3글자 제목 중심으로 만든다. 타일은 최소 높이 96 CSS px, 다른 버튼도 최소 48 px이다.
- 타일을 누르면 해당 연습 하나만 실행한다. 성공 후 `다른 연습`, `한 번 더`를 제공한다.
- `처음부터 연습`은 이동 → 패스 → 슛 → 태클 순서로 진행한다. 단계 사이에 직접 `다음 연습`을 누른다.
- 네 단계 완료 후 `경기 시작`, `연습 메뉴`를 제공한다. 경기 시작은 팀 선택으로 이동한다.
- `바로 경기하기`는 언제든 사용한다. 건너뛰기에 불이익이 없다.
- 최초 경기 시작에서 기존 안내 대신 이 메뉴를 한 번 보여준다. 연습/월드컵 진입 의도는 session.pendingMode에 보관하고 팀 선택까지 유지한다. 기존 월드컵 이어하기 버튼도 같은 규칙을 적용한다.
- 홈에서 조작 연습을 직접 연 경우 pendingMode는 practice다. 국가 선택값과 cupRound는 변경하지 않는다.
- 완료 배지는 현재 연습 세션에서만 표시한다. 이번 단계에 새 영구 진행률 저장 키를 추가하지 않는다.
- 기존 `kkoma-tutorial-done`는 `바로 경기하기` 또는 순차 연습 완료 시 true로 저장한다. 단일 연습 성공만으로 전체 연습 완료라고 표시하지 않는다.

## 4. 플레이 화면 구성

- 상단: `이동 연습 · 1/4`, 연습 메뉴 버튼, 일시정지 버튼. 실제 경기 점수/시계 대신 표시한다.
- 중앙: 기존 경기장과 실제 선수/공, 목표 링과 손가락 시범.
- 하단: 짧은 지시 한 문장, `다시 해보기`. safe-area를 반영한다.
- 태클 연습에만 기존 태클 버튼을 노출한다. 일반 드래그 안내와 겹치지 않게 한다.
- 진행 중 안내는 독립된 `#tutorial-overlay`에 둔다. overlay 전체는 `pointer-events:none`, 버튼만 `pointer-events:auto`다. 기존 #screen은 비워 Canvas 입력을 유지한다.
- 성공 시 appScreen='tutorial-result', game.paused=true, clearPointer 및 lastTap 초기화 후 #screen에 작은 결과 카드를 표시한다. 손을 계속 누른 상태로 이동에 성공해도 이후 pointerup이 킥을 만들지 않아야 한다. 다음/재시도에서만 match/playing 상태로 돌아간다.
- 실패 안내 대신 `한 번 더 해보자!`. 선택한 연습을 그대로 유지하고 장면만 재설정한다.

색과 모양을 함께 쓴다: 목표 위치는 별이 들어간 링, 패스 동료는 링+동료 아이콘, 슛 목표는 골대 아이콘+주황 선, 태클 상대는 공 가진 상대 표시+두 번 탭 아이콘. 글을 읽지 않아도 목표를 구분할 수 있게 한다.

## 5. 네 연습의 장면과 실제 성공 판정

좌표는 기존 world 좌표다. 아래 배치는 구현 출발점이며, 360×800/412×915의 project() 결과로 UI 가림을 확인하고 장면 배치만 조정한다. 투영 계산을 바꾸지 않는다.

| 단계 | 장면 | 지시 | 성공 조건 |
|---|---|---|---|
| 이동 | 우리 선수 index 6, (-8,62), 공 소유. 목표 (0,62), cameraY=52.5 | `별까지 끌고 있어요` | 실제 포인터를 누르고 이동해 목표 2.5 world 단위 안에 도착. 임의 이동/시범은 인정하지 않음 |
| 패스 | index 6 (-8,58), 동료 index 9 (6,48), 공 소유. 동료는 제자리. cameraY=52.5 | `친구 쪽으로 끌고 손을 떼요` | 우리 선수가 실제 kick(shot=false)을 실행하고 지정 동료가 실제 포구. 드리블 접촉·클릭·시범은 인정하지 않음 |
| 슛 | index 6 (0,18), attackDir=-1, 전방 동료/GK 없음. cameraY=31 | `골대로 끌고 손을 떼요` | 실제 shot=true 킥 이후 공이 상대 골문 안을 통과하여 기존 scoreGoal 경로에 도달 |
| 태클 | 우리 index 6 (0,52), 공 가진 상대 index 17 (0,44), cameraY=52.5. 상대는 제자리 | `공 가진 상대를 두 번 톡톡!` | 실제 tryManualTackle로 추격하고 completeManualTackle이 성공. 공이 우리 소유가 된 것만으로 통과하지 않음 |

태클 버튼도 같은 성공 경로를 사용한다. 우선 화면에서는 두 번 탭을 시범으로 보여주고, 6초 동안 성공하지 못하면 태클 버튼을 강조한다. 버튼으로 성공해도 정식 성공으로 인정한다.

### 공통 연습 환경

- 기본 우리 팀은 대한민국, 상대는 브라질로 고정해 빨강/노랑으로 구별한다. 실제 국가 선택값은 그대로 보존한다.
- 장면에 필요한 1~2명만 플레이에 참여한다. 등장하지 않는 선수는 표시·타깃 선택·충돌·포구에 관여하지 않는다.
- 동료 자동 전진, 상대 슛/패스/압박, 자동 태클은 연습에서만 정지한다. 조작 중인 선수 이동과 수동 태클 추격은 그대로 실행한다.
- 이동에 성공하면 누른 손을 강제로 놓게 요구하지 않고 바로 입력을 정리한 뒤 성공 화면으로 간다.
- 패스/슛 실행 후 최대 3 활성 초 내 성공하지 못하거나 공이 밖으로 나가면 0.7 활성 초 뒤 장면을 재설정한다. 태클 추격은 기존 2.5초 한도 후 재시도한다.
- 입력이 없는 아이에게 실패나 강제 재시도를 띄우지 않는다. 도움만 보여준다.
- 성공 메시지는 `잘했어!`, 패스 `친구가 공을 받았어!`, 슛 `골!`, 태클 `공을 빼앗았어!`로 짧게 쓴다.

## 6. 시각적 시범과 도움

- 이동/패스/슛: 반투명 손가락 원이 시작점 → 목표 방향으로 이동한다. 이동은 끝에서 잠깐 유지, 패스/슛은 끝에서 사라져 손을 떼는 시점을 보여준다.
- 태클: 상대 위에 원이 두 번 축소·확대되는 시범을 보여준다.
- 시범은 Canvas 그림만 그린다. PointerEvent를 발생시키거나 실제 공/선수를 이동시키지 않는다.
- 사용자가 터치하면 시범을 숨기고 기존 흰 점선·청록 패스·주황 슛 안내에 집중한다.
- 도움 시간은 game.elapsed 기준으로 누적해 일시정지·탭 전환 동안 흐르지 않는다.
- `prefers-reduced-motion`에서는 움직이는 시범 대신 고정 화살표와 시작/끝 원을 표시한다.
- 새 PNG, 영상, 사운드, 라이브러리는 필요 없다. 기존 선수 sprite와 Canvas fallback을 사용한다.

## 7. 최소 변경으로 연결하는 방법

### 상태

별도 엔진이나 범용 이벤트 시스템을 만들지 않는다. 단일 연습 세션 상태와 기존 game의 연습 표시만 둔다.

```text
tutorialSession:
  flow: single | all
  stepId: move | pass | shot | tackle
  phase: playing | success
  completed: 현재 세션의 완료 단계
  pendingMode: practice | cup
  sceneToken: 재설정마다 증가
  action: 이번 장면에서 실제 실행한 킥/태클 정보
  retryAt: 장면 재설정 예정 game.elapsed 또는 null
  activePlayers: game.players의 활성 선수 객체 참조
```

메뉴·연습을 종료할 때 위 상태를 초기화한다. 성공 후 실제 경기에 들어갈 때 새 startMatch를 실행하고, 튜토리얼 game 객체를 재사용하지 않는다.

### 기존 함수 연결

1. `showTutorial`을 연습 메뉴 진입점으로 교체하고 step 목록은 고정 네 가지로 둔다. 시작/다시 보기 버튼 라우팅을 갱신한다.
2. `startMatch(tutorialStepId=null)`에 제한된 연습 분기를 넣는 방법을 권장한다. 인자가 없을 때 현재 정상 경기는 그대로 실행한다. 연습일 때 game.mode='tutorial', 고정 팀, session 및 초기 장면을 지정하고 메뉴 BGM을 유지한다. 전역 mode/selectedCountry/cupRound를 연습값으로 덮어쓰지 않는다.
3. 22명 roster와 index를 유지한다. game.players[6], [17], manualTackler index 접근을 깨뜨리는 배열 축소는 금지한다. `playersInPlay()`처럼 연습이면 activePlayers, 본경기면 game.players를 반환하는 작은 helper를 사용한다.
4. 활성 선수 목록을 nearestPlayer/nearestFieldPlayer/nearestPlayers, laneRisk, passTargetFor/passTargetAtFinger/bestAiPass, 이동 loop, 포구 loop, draw의 대상에 일관되게 적용한다. resetPositions의 22명 초기화와 배열 index 조회는 원래 roster를 사용한다. helper는 본경기에서 기존 배열을 그대로 반환한다.
5. `updateMatch`는 공·포인터·추격의 공통 처리 경로를 유지한다. 연습 조건일 때 경기 전후반/종료 처리와 NPC AI/자동 태클만 건너뛴다. 골문 안 득점은 기존 scoreGoal 경로로 보내고, 골문 밖 골라인/터치라인 이탈은 연습 재시도로 보내 일반 골킥 대기가 시작되지 않게 한다. 별도 updateTutorialPhysics나 연습 전용 gesture resolver를 복사하지 않는다.
6. `kick`에서 연습 action을 기록한다. 실제 공 배급과 판정은 기존 구현 그대로다. `setPossession`의 포구 후 목표 동료와 action을 확인한다. `completeManualTackle`에서 수동 태클 성공을 기록한다. `scoreGoal`에서 슛 연습이면 성공 처리 후 return하여 일반 킥오프/결과 저장으로 진입하지 않는다.
7. 단계·장면을 재설정할 때 clearPointer/lastTap/manualTackler/재개 상태/킥 타이머/action을 초기화한다. sceneToken이 다른 이전 action으로 성공 처리하지 않는다. 임의 setTimeout 성공 callbacks를 만들지 않는다.
8. 성공 처리에는 단일 guard를 둔다. phase가 playing일 때만 한 번 success로 바꾼다. 같은 프레임 여러 포구/득점 판정으로 다음 단계를 두 번 넘기지 않는다.
9. `pauseGame`과 resume/retry/home 라우팅을 연습 종류에 맞게 표시한다. 연습의 다시 시작은 해당 단계 재설정, 일반 경기 retry는 현재 startMatch다. 연습 resume은 메뉴 BGM을 복귀시킨다. 새 tutorial-overlay 버튼은 별도 click 위임으로 연결하고, 기존 #screen의 라우팅으로 자동 전달된다고 가정하지 않는다.
10. `finishMatch`가 연습 상태에서 호출돼도 월드컵 저장·승부차기·일반 경기 결과로 진행하지 않게 방어한다. 정상 경기는 기존 분기 그대로다.

## 8. 음악 및 저장 데이터

- 연습 메뉴와 모든 연습에서 Soccer Dash 두 곡의 기존 메뉴 음악을 사용한다. 연습 진입마다 곡을 재선택하거나 처음부터 재생하지 않는다.
- 실제 경기를 시작하면 Kickoff Bounce/Pocket Pitch 무작위 경기 음악으로 전환한다.
- pause/visibilitychange에서는 음악과 연습 시간을 정지한다. 복귀 시 남은 연습 상태와 같은 음악을 이어간다.
- mute 설정을 유지한다. 브라우저 첫 사용자 동작 전 자동재생 제한도 기존 playMusic의 재시도 정책을 사용한다.
- 기존 cup 기록, muted, selectedCountry는 연습 전후 동일해야 한다. 새 영구 저장 키는 추가하지 않는다.

## 9. Luna 구현 순서와 파일

| 순서 | 구현 | 관련 파일 | 단계 통과 기준 |
|---|---|---|---|
| P1 | 메뉴, single/all 흐름, 시작/건너뛰기, touch overlay | game.js, game.css, index.html | 타일과 버튼이 360×800에 들어가고 pendingMode 유지 |
| P2 | 활성 선수 목록·연습 상태 초기화·이동/패스 연습 | game.js, tests/mobile-logic.mjs | 본경기 회귀 테스트 통과, 실제 이동과 지정 동료 포구로만 성공 |
| P3 | 슛/태클 연습·도움 시범·성공 화면 | game.js, game.css, tests/mobile-logic.mjs | 시범·자동 수비·잘못된 동작으로 완료 불가 |
| P4 | pause/취소/종료/음악/저장 검증, 문서와 모바일 QA | README.md, 테스트·필요 시 visual-qa.mjs | 상태 누수 없고 실제 경기 진입이 정상 |

테스트와 브라우저 검증은 각 단계에서 필요한 만큼 실행한다. 신규 테스트는 기존 mobile-logic VM harness와 실제 pointer 이벤트를 우선 사용한다. 기존 60회 패스/40회 슛·수비·GK·음악 회귀 테스트를 제거하거나 assertion을 약화시키지 않는다.

## 10. 필수 재현 테스트

1. 메뉴에서 네 개 타일로 각각 들어가고 다시 연습 메뉴로 돌아온다. all 흐름에서 move→pass→shot→tackle 순서, single 흐름은 자동으로 다음 단계로 가지 않는다.
2. 이동: 터치 없이 경과, 손가락 시범만 재생, 빈 곳 탭은 성공 불가. 실제 드래그로 목표에 도착하면 성공 1회. 성공 당시 손이 눌려 있어도 pointerup에서 유령 패스가 발생하지 않는다.
3. 패스: 그냥 탭/드리블은 성공 불가. 0.1/1/3초 드래그 후 손을 놓아도 실제 패스와 지정 동료 포구로 성공. 빗나가면 같은 단계 재시도. 재설정 전 action은 무효다.
4. 슛: 실제 shot=true 및 실제 골문 통과에만 성공. 원거리 패스나 임의 score 값 대입을 성공 증거로 쓰지 않는다. 실패·경계 이탈 후 다시 연습 가능하다.
5. 태클: 상대 소유권은 시범·일반 자동 수비로 바뀌지 않는다. 실제 두 번 탭과 태클 버튼 양쪽에서 추격→접촉→성공. 단일 탭·먼 곳 두 번 탭·연타 중복 완료는 불가다.
6. 비활성 선수가 표시·패스 목표·공 포구·nearest defender에 포함되지 않는다. 본경기에서는 22명 정상 처리된다.
7. pointercancel/lostpointercapture/두 번째 손가락/visibilitychange/일시정지 중 성공이나 킥이 생기지 않는다. 복귀 버튼 이후 같은 단계에서 재개한다.
8. 성공 화면·도움·재시도 대기 중 나가기/재시작/새 경기 후 예전 입력이나 action이 남지 않는다.
9. 튜토리얼을 150초 이상 열어도 하프타임/경기 종료가 나타나지 않는다. 정상 경기 75/150초 동작은 유지된다.
10. 월드컵 진입→연습→팀 선택은 cup 의도를 유지한다. 연습 단계 성공/실패/건너뛰기로 cupRound/localStorage 기록이 바뀌지 않는다.
11. 메뉴·연습 BGM 유지, pause/음소거/복귀, 실제 경기 시작의 BGM 전환을 확인한다. sprite 실패 시 Canvas fallback도 확인한다.
12. 360×800, 390×844, 412×915 및 대표 데스크톱 크기에서 목표·공·선수·두 번 탭 위치·버튼이 가려지지 않는다. 터치 overlay 중앙에서 Canvas가 입력을 받는다. reduced-motion에서도 지시를 이해할 수 있다.

필수 명령:

```powershell
node --check game.js
node --check tests/mobile-logic.mjs
node tests/mobile-logic.mjs
git diff --check
```

구현 중 80% 기준은 각 단계의 진입→실제 행동→성공→재시도 흐름과 모바일 입력/화면 내 UI/오류 없는 실행이다. 90% 기준은 네 단계 전체 흐름·본경기 회귀·스크린샷 QA·음악·저장 보존 및 의도치 않은 큰 diff가 없는 상태다. 각 항목에 PASS/FAIL/NOT VERIFIED와 실제 근거를 기록한다. Android 실기기 FPS/손맛과 어린이의 이해도는 실제 확인 전 NOT VERIFIED다. 구현 diff 독립 검토는 연결된 ChatGPT Web이 있으면 사용하고, 없으면 검토를 실행하지 않았음을 기록한다.
