# 꼬마 축구 월드컵 우승 엔딩 — Luna 구현 설계

작성: 2026-10-03. 대상: `SeungMin-Park-psm1757/kkoma-soccer-game-demo`.
분석 기준: 최신 `origin/main`, `239801984d8daf95991c58a1d4d583d61c4f8070`.
상태: **P1~P4 구현, P5 로컬 검증 진행 중. 신규 일러스트 제작·커밋·푸시는 아직 하지 않음.**

## 1. 목표와 구현 범위

초등학교 1학년이 우승 후 “내가 정말 해냈다!”고 느끼고, 이긴 경기와 재미있는 축구 이야기를 짧게 돌아본다.

- 기본 엔딩은 **7장**, 다른 나라 선수 이야기를 추가하는 경우 **8장**이다. 대사는 장마다 1~2문장이다.
- 실제로 이긴 상대·점수·승리 방식을 비교한다. 기록이 없는 과거 경기는 만들어내지 않는다.
- **48개 국가 각각 3개 이야기**, 총 144개 슬롯을 준비한다. 아래 국가별 원고와 선수 일화 교체 규칙을 그대로 사용한다.
- 좋아하는 선수·사진은 아직 지정되지 않았다. 기본은 현재 게임 캐릭터, 국가별 kit, 창작 장면이다. 실제 사진은 사용자가 제공한 파일과 사용 가능한 사진만 연결한다.
- 유명 선수의 실제 이야기는 출처와 사건 연도를 붙인다. 선수의 직접 대사처럼 꾸미거나 실제 선수가 아들에게 메시지를 보낸 것처럼 표현하지 않는다.
- 경기를 잘하는 법을 시험하거나 훈계하는 엔딩이 아니다. 따뜻한 축하, 짧은 발견, 작은 웃음을 우선한다.
- AI, 물리, 조작, 국가 능력치, 유니폼 데이터, 카메라, 경기장, 토너먼트 대진 방식은 이번 범위에서 바꾸지 않는다.

가장 간단한 구현은 기존 결과 overlay·버튼·저장 helper를 재사용하고, 경기 기록과 엔딩 카드만 추가하는 것이다. 새 엔진·라이브러리·서버는 필요 없다.

## 2. 현재 코드에서 확인한 사실

| 코드/데이터 | 현재 동작 | 설계에 미치는 영향 |
|---|---|---|
| `roundNames` | 32강 → 16강 → 8강 → 4강 → 결승 | 우승까지 5개 승리 기록. 실제 월드컵 전체 형식으로 확장하지 않음 |
| `kkoma-cup-round` | 다음 라운드 숫자만 저장 | 상대·점수·골 순서 기록을 새로 보관해야 함 |
| `startMatch()` | 국가·상대·round·score·elapsed 생성 | 경기 시작 시 해당 경기의 득점 기록 배열 초기화 |
| `chooseOpponent()` | 선택 국가 제외 무작위 상대 | 같은 상대가 다시 나올 수 있음. 국가가 아니라 round 기준으로 기록 |
| `showTeams()` | 라운드 사이 국가 변경 가능 | 매 경기 당시의 우리 팀도 기록. 모두 같은 나라였다고 가정하지 않음 |
| `scoreGoal(side)` | 점수 증가 후 킥오프 처리 | 여기서만 골 순서/시각을 관찰. 골·포지션 로직은 그대로 둠 |
| `finishMatch()` | 결승 승리면 기존 점수 패널에 `월드컵 우승!` 표시 | 우승 조건은 그대로 사용하고 이 분기에만 엔딩 진입 |
| 승부차기 | 동점일 때 자동 생성한 두 팀 합계 | 합계만 소개. 실제 킥 순서·선수·골키퍼 선방을 지어내지 않음 |
| 우승 이후 | round=4가 남아 다시 결승 가능 | 새 월드컵과 엔딩 다시 보기의 의미를 명시적으로 분리 |
| `finishMatch()` 재호출 | 현재 ended 선행 guard 없음 | 승부차기 재생성·중복 기록을 막는 guard 필요 |
| `game.mode === 'tutorial'` | 튜토리얼 종료 별도 처리 | 튜토리얼/연습 경기는 우승 기록에 쓰지 않음 |
| `playMusic('menu',true)` | 결과에서 기존 메뉴 음악 재생 | 기존 메뉴 곡 유지. 승리 전용 음악이 있다고 가정하지 않음 |
| `store.get/set` | JSON 처리/저장 예외를 catch | 새 기록도 이 helper 재사용, 실패해도 엔딩은 세션에서 표시 |

이전 PR #5는 이미 main에 병합되었다. Luna 구현은 최신 main에서 **새 브랜치·새 PR**로 진행한다.

## 3. 어린이가 보는 엔딩 흐름

```text
결승 승리
  → 1. 트로피와 축하
  → 2. 내가 이긴 팀들
  → 3. 기억에 남는 승리 비교
  → 4. 우리 나라 이야기 ①
  → 5. 우리 나라 이야기 ② / 실제 선수 이야기
  → 6. 우리 나라 이야기 ③
  → [다른 나라 실제 선수 이야기: 해당 국가 일화가 없으면 1장 추가]
  → 7 또는 8. 우승 기념사진과 마무리
```

### 카드별 구성과 대사 예시

아래 경기 결과는 **디자인 예시**다. 구현에서 고정값으로 사용하지 않는다.

| 장 | 그림/내용 | 짧은 대사 |
|---|---|---|
| 1 | 트로피, 선택 국가 유니폼의 꼬마 선수, 짧은 종이 조각 | `와! 대한민국이 우승했어!` / `네가 우리 팀을 이끌었구나!` |
| 2 | 라운드별 국기·상대·실제 점수 최대 5줄 | `우승까지 이런 팀들을 만났어!` / `한 경기씩, 여기까지 왔네!` |
| 3 | 비교 배지 최대 2개: 가장 많은 골, 가장 아슬아슬한 승리 등 | `브라질전에서는 3골을 넣었어!` / `프랑스전은 승부차기 끝에 이겼네!` |
| 4 | 국가 이야기 ①: 작은 연습 장면 | `작은 공을 톡톡!` / `처음에는 천천히 차도 괜찮아.` |
| 5 | 국가 이야기 ②: 실제 선수 일화 또는 창작 팀 장면 | `손흥민은 2025년 우승 뒤 동료들에게 고마움을 전했어.` / `축구는 함께 만드는 기쁨이네!` |
| 6 | 국가 이야기 ③: 익살스러운 축하 장면 | `트로피가 번쩍!` / `우리 팀의 웃음도 번쩍!` |
| 추가 | 다른 국가의 선수 이름·국기·연도 표시 | `포르투갈의 호날두는 골을 넣을 기회를 친구에게 패스했어.` / `그 패스로 골이 들어갔대!` |
| 마지막 | 트로피+최종 팀명+기록 요약 기념 카드 | `오늘의 우승 이야기는 여기까지!` / `다음에는 어떤 팀과 놀아볼까?` |

문장 목표는 한 문장 약 15~35자다. 국가명·선수 이름 때문에 길어지면 문장을 나누고, 한 카드 본문은 최대 3줄로 검수한다. 외국 이름 발음·전문 용어·OVR·긴 숫자 비교는 줄인다.

### 조작과 모바일 배치

- **자동 넘김 없음.** 큰 `다음 ▶` 버튼으로 한 장씩 읽는다. “지나가는 대사”는 이 순서형 메시지로 구현한다.
- 처음부터 문장을 모두 표시한다. 글자가 한 글자씩 나오는 연출·강제 대기·퀴즈는 넣지 않는다.
- `◀ 이전`, `다음 ▶`, `메뉴로`를 제공한다. 스와이프·더블탭은 엔딩 필수 조작에 넣지 않는다.
- 상단 `우승 이야기 · 1/7`, 중앙 그림, 하단 말풍선과 버튼. 터치 영역 최소 48 CSS px.
- 화면 아무 곳이나 탭하면 넘어가는 방식은 쓰지 않는다. 다음 버튼을 연타해도 한 탭은 한 장만 넘기고 이벤트가 중첩되지 않게 한다.
- 360×800, 390×844, 412×915에서 본문·버튼이 보이도록 한다. safe-area 반영, 본문 18~22px, 긴 국가는 줄바꿈.
- 기록 5줄은 짧은 리스트로 표시한다. 공간이 부족하면 기록 영역만 스크롤하며 버튼은 화면 안에 남긴다.
- 실제 선수 카드의 작은 표시는 `실제 축구 이야기 · 2025`, 창작 카드는 `꼬마 선수 이야기`다.
- 마지막 주 버튼은 `새 월드컵 시작`, 보조 버튼은 `이야기 다시 보기`, `메뉴로`다.
- 엔딩 중 경기 입력은 비활성화한다. 카드 탭이 패스·슛·태클로 전달되지 않아야 한다.
- 처음 1장에만 1~1.5초 종이 조각을 최대 30개 보여준다. reduced-motion에서는 정지 그림으로 대체한다.
- 현재 메뉴 BGM/음소거 설정을 유지한다. 자동 음성·새 음악 파일·국가별 음성 제작은 별도 요청 때 진행한다.
- 탭 전환 후에는 읽던 카드로 돌아온다. 엔딩에서 경기 시계나 AI가 다시 시작되면 안 된다.

## 4. 실제 승리 기록과 비교 규칙

### 최소 저장 내용

추가 localStorage 키는 **`kkoma-cup-journey-v1` 하나**다. 기존 `kkoma-cup-round`, 튜토리얼, 음악 키는 유지한다.

```js
{
  version: 1,
  current: {
    startedRound: 0,
    completed: false,
    wins: [
      {
        round: 0,
        homeId: 6,
        awayId: 1,
        score: [3, 1],
        shootout: null,
        goalEvents: [
          { elapsed: 20, side: 1, score: [0, 1] },
          { elapsed: 40, side: 0, score: [1, 1] },
          { elapsed: 90, side: 0, score: [2, 1] },
          { elapsed: 120, side: 0, score: [3, 1] }
        ]
      }
    ]
  },
  lastChampion: null // 우승 시 { countryId, wins, storyIds } 복사본 저장
}
```

위 score는 예시다. `lastChampion`은 JSON으로 저장 가능한 값의 복사본이며 `game`·선수·Canvas·Image 객체를 넣지 않는다. 시간은 기존 게임 elapsed의 초 단위이며 실제 축구의 90분으로 바꾸어 부르지 않는다.

### 기록 시점과 중복 방지

1. `startMatch()`에서 실제 경기의 `game.goalEvents=[]` 초기화.
2. `scoreGoal()`의 튜토리얼 분기 이후, 점수가 올라간 직후 실제 score 복사본 기록. 킥오프 이후에 기록하지 않는다.
3. `finishMatch()` 첫 guard에 `game.ended` 추가. 가드 이후 한 번만 승부차기 합계 생성/기존 승리 판정 수행.
4. 컵 승리일 때 현재 round의 스냅샷 저장 후 다음 round 진행. 승리 배열은 round 기준 최대 5개다.
5. 컵 패배는 진행·기존 승리 기록을 보존한다. 패배를 이긴 상대 목록에 넣지 않는다.
6. 결승 승리 기록까지 포함해 `lastChampion` 복사, current.completed=true 저장 후 엔딩 표시.
7. 우승 이야기 다시 보기는 점수·라운드·기록·음악 추첨을 다시 실행하지 않는다.

### 무엇을 “어떻게 이겼는지”로 말할 것인가

| 표시 | 실제 근거 | 어린이 문장 예시 |
|---|---|---|
| 골을 가장 많이 넣은 경기 | 우리 팀 정상 경기 득점 최댓값 | `{상대}전에서 {득점}골을 넣었어!` |
| 아슬아슬한 승리 | 정상 경기 득실차 최솟값. 승부차기 승리는 차이 0으로 분류 | `{상대}전은 한 골 차이였어!` 또는 `승부차기로 이겼어!` |
| 골문을 지킨 경기 | 정상 경기 상대 득점 0 | `{상대}전은 상대에게 골을 내주지 않았어!` |
| 뒤집은 경기 | goalEvents에서 뒤졌던 점수 확인 + 정상 경기 최종 승리 | `먼저 골을 내줬지만, 끝에는 이겼어!` |

- 비교 카드에서는 서로 다른 사실 최대 2개만 고른다. 우선순위: 역전/승부차기 → 가장 많은 골 → 무실점 → 한 골 차이.
- 동률은 먼저 치른 라운드를 고른다. 같은 상대가 두 번 나오면 반드시 `8강`, `결승` 등 라운드를 붙인다.
- 기록이 1개면 “가장” 비교를 사용하지 않고 그 경기의 점수·승리 방식만 말한다.
- 0:0 승부차기 우승을 `많은 골을 넣었어`로 칭찬하지 않는다. 정상 득점과 승부차기 합계를 분리한다.
- 골문을 지킨 것은 팀 성과다. 저장되지 않은 골키퍼 선방 횟수나 특정 선수의 득점을 주장하지 않는다.
- 패스 성공률, 태클 수, 슛 정확도, 상대 국가 강약 평가는 이번 단계에서 만들지 않는다.
- 중간에 국가를 바꿨으면 각 줄에 실제 home 국가도 표시하고 `네가 이끈 팀들이 여기까지 왔어!`라고 말한다. 마지막 국가의 이야기 3개를 표시한다.

### 기존 사용자/저장 실패/새 대회

- 예전 사용자는 round=2~4여도 과거 경기 기록이 없다. 새 시스템 적용 시 `startedRound=cupRound`, wins=[]로 시작한다.
- 빠진 기록을 빈 점수·가짜 국가로 채우지 않는다. 카드 2 제목은 `이번에 기록한 경기`, 문장은 `남아 있는 경기 기록을 함께 보자!`다. 5전 전승이라고 단정하지 않는다.
- 저장 데이터는 version, country ID, round 0~4, 비음수 정수 점수, 유효한 승리, 중복 round, goalEvents 순서를 검사한다. 비정상 값은 버리고 기존 라운드를 기준으로 복구한다.
- 골 이벤트는 정상 경기 최종 점수/승부차기 판정에 영향을 주지 않는다. 데이터가 없거나 맞지 않으면 역전 칭찬을 생략한다.
- 저장 키 간 상태가 어긋나면 숫자 라운드를 기준으로 계속 진행한다. 현재 round 이상인 오래된 wins는 제외한다. 단 completed=true인 유효한 결승 우승 기록은 엔딩으로 연결한다.
- localStorage 쓰기가 실패해도 메모리의 실제 기록으로 엔딩을 끝까지 볼 수 있어야 한다. 새로고침 뒤 기록 복원이 된다고 약속하지 않는다.
- `새 월드컵 시작`을 눌렀을 때만 current 초기화 + cupRound=0 저장 + `showTeams('cup')` 진입. lastChampion은 보존한다.
- 완료된 대회에서 기존 `월드컵 이어하기`는 우승 이야기로 연결한다. 홈의 버튼 수/전체 레이아웃은 그대로 둔다. 진행 중인 새 대회가 있으면 기존 이어하기를 우선한다.
- 홈에 lastChampion이 있으면 작은 `🏆 지난 우승 이야기` 링크를 추가할 수 있다. 큰 경기 시작/조작 연습/이어하기 버튼을 밀어내지 않는다.
- 우승의 `다시 경기`는 새 월드컵으로 대체한다. 결승만 반복하면서 이전 4승을 새 대회 기록처럼 재활용하지 않는다.

- 위 8개 국가는 ② 슬롯을 해당 실제 선수 이야기로 교체한다. 엔딩은 총 7장이다.

- 실제 선수 사진이 없어도 별/공/패스 장면과 이름으로 읽을 수 있어야 한다. 대한민국 창작 꼬마 얼굴을 손흥민의 얼굴이라고 표시하지 않는다.
- 선수 관련 이적·수상 변경을 런타임 웹 검색이나 외부 API로 불러오지 않는다. 콘텐츠는 저장소에서 검토한 정적 데이터다.

## 7. 그림·사진 연결 방식

처음에는 **공유 창작 장면 3개**와 기존 국가별 kit 색상을 재사용한다. 48×3개의 별도 그림 제작이 엔딩 작동의 전제 조건은 아니다. 원하면 국가별 사진/삽화를 아래 슬롯에 나중에 교체한다.

```text
assets/ending/
  shared/practice.webp      # 공과 연습 콘, 넓은 여백
  shared/teamwork.webp      # 친구 둘의 패스/하이파이브
  shared/celebration.webp   # 트로피와 기념사진
  korea/story-1.webp        # 국가별 선택 자산; 아직 없어도 정상
  korea/story-2.webp
  korea/story-3.webp
  ...                      # 다른 국가도 필요할 때만 생성
```

- 국가 이야기 데이터의 `image`가 없으면 공유 장면 → 현재 Canvas/간단한 kit 색상 일러스트 순으로 fallback.
- 실물 사진은 별도 `alt`, `credit`, `sourceUrl`, `licenseNote`와 함께 등록한다. 파일이 제공되기 전에는 가짜 사진 경로를 로딩하지 않는다.
- artwork 대상 표시 크기는 약 260×160 CSS px, 권장 파일 약 512×320 WebP, 장면당 목표 100KB 이내. 인물 그림은 투명 배경을 사용할 수 있다.
- 모든 자산을 처음부터 preload하지 않는다. 현재 카드와 다음 카드만 미리 로드한다. 404/오류 시 fallback, 깨진 이미지 아이콘 없음.
- 기존 대한민국 sprite는 원본·프레임·manifest를 그대로 보존한다. 엔딩의 꾸밈을 위해 물리 좌표나 sprite anchor를 수정하지 않는다.
- 카드 텍스트는 HTML 그림 안에 넣지 않고 DOM 본문으로 표시한다. `textContent`/신뢰된 정적 템플릿으로 넣고 사용자 사진 설명을 raw innerHTML로 주입하지 않는다.

공유 그림을 의뢰할 때 사용할 프롬프트 기준:

> 밝고 친근한 한국 어린이 모바일 축구게임의 엔딩 카드용 가로 8:5 삽화. 기존의 둥근 머리와 짧은 몸을 가진 치비 꼬마 선수 비율을 유지. 부드러운 cel shading, 명확한 실루엣, 낮은 배경 복잡도. [연습 콘 앞에서 공을 차는 장면 / 친구 둘이 공을 주고받는 장면 / 트로피 옆에서 웃는 기념사진] 중 한 장면. 인물·축구화가 잘리지 않음. 유니폼은 가상의 단순 디자인, 실제 선수 얼굴·브랜드·협회 문양 없음. 글자·UI·워터마크 없음. 중앙에 주요 장면, 말풍선은 게임 코드에서 별도 표시.

## 8. 구현할 파일과 최소 연결

| 파일 | 변경 |
|---|---|
| `game.js` | 경기 스냅샷/골 이벤트, 우승 guard, 엔딩 카드 생성·이동·새 대회·다시 보기. 기존 화면 이벤트 위임 사용 |
| `ending-content.js` (신규) | 48×3 원고와 검증된 일화·출처의 정적 데이터만. 순수 데이터 객체를 `window.KKOMA_ENDING_CONTENT`로 노출 |
| `index.html` | game.js 이전에 ending-content.js를 defer로 로드. 런타임 함수는 새 파일로 옮기지 않음 |
| `game.css` | 기존 panel/game-button 재사용, 엔딩 그림/말풍선/기록 리스트/반응형/축하 효과 스타일만 추가 |
| `tests/mobile-logic.mjs` | 재현 및 저장·우승·카드·fallback 회귀 테스트. content.js도 VM에서 읽고 시작 |
| `tests/visual-qa.mjs` | 기존 도구에 ending 모드/fixture 추가, 모바일 3개 폭의 실제 DOM 화면 확인 |
| `.github/workflows/verify.yml` | 신규 content.js 문법 검사 한 줄 추가 |
| 이 설계 문서 | 구현 후 단계별 PASS/FAIL/NOT VERIFIED와 실제 변경점을 기록 |

데이터 예시:

```js
{

    6: [

      {id:'country-6-2', kind:'fact', factId:'son-team-2025'},
      {id:'country-6-3', kind:'fiction', lines:['트로피가 번쩍!','우리 팀의 웃음도 번쩍!'], image:null}
    ]
  },
  facts: {
    'son-team-2025': {
      countryId:6, player:'손흥민', eventYear:2025,
      lines:['손흥민은 2025년 우승 뒤 동료들에게 고마움을 전했어.','함께 만든 우승이라 더 기뻤겠네!'],
```

- 파일 분리는 긴 원고를 game.js에서 떼어 읽기 쉽게 하려는 목적이다. 스토리 엔진·상태관리 라이브러리·범용 scene manager를 만들지 않는다.
- content.js 자체가 없거나 잘못 로드돼도 game.js는 부팅된다. 임시 기본 이야기 3개로 총 7장을 표시하고 QA에 콘텐츠 미완료로 기록한다.
- 기본 데이터/이미지 누락 fallback은 회복 경로다. 정식 완료 기준은 48개국 모두 정상 콘텐츠를 가진 상태다.
- 외부 출처 링크는 플레이 흐름에 끼우지 않는다. 작은 `이야기 출처` 버튼을 펼쳤을 때 제목·연도·링크가 보이며, 닫으면 읽던 카드에 머문다.
- `showEnding(snapshot)`은 appScreen='ending'로 전환, 기존 game.ended 유지, pointer/lastTap 정리, HUD/조작 가이드/태클 버튼 숨김. 별도의 경기 loop는 만들지 않는다.

## 9. P1부터 순서대로 구현

### P1 — 기존 결함 재현과 실제 경기 기록

구현: 다섯 라운드의 점수/국가/득점 흐름 저장, 구버전 라운드 이어가기, 종료 중복 guard. 중복 종료 전 재현 테스트 실패를 확인하고 수정 뒤 모바일 로직 테스트 통과.

먼저 현재 코드에서 실패하는 회귀 테스트를 추가한다.

1. `finishMatch()`를 두 번 호출해 승부차기/round/저장 내용이 바뀌지 않아야 함.
2. 컵 32강~결승까지의 상대·실제 score가 저장되어야 함.
3. 패배/재도전/튜토리얼이 승리 기록을 추가하거나 삭제하지 않아야 함.
4. 기존 round=2만 있는 사용자에게 앞의 두 상대·점수를 만들어 주지 않아야 함.

테스트 실패를 확인한 뒤 guard·스냅샷·저장 검사·goalEvents를 추가한다. 기존 물리/AI 호출 순서는 유지한다.

### P2 — 7~8장 엔딩과 승리 비교

구현: 수동 이전/다음, 기록/비교, 우승 다시 보기, 새 대회, 홈의 지난 우승 링크. 실제 final game 종료 후 엔딩이 열림.

1. 컵 결승 승리에서만 엔딩 진입.
2. 7장 기본 카드, 다음/이전/마지막 버튼, 점수 리스트/비교 배지 구현.
3. 신규 대회 초기화, 진행 이어하기, 우승 다시 보기, 저장 실패 fallback.
4. 실제 득점·승부차기 근거로 문장 생성. 과거 기록 없음/국가 변경/반복 상대 처리.

단계 완료 기준: 이미지가 없어도 끝까지 읽고 새 컵 32강으로 시작 가능, 우승 기록은 다시 보기에서 변하지 않음.

### P3 — 국가별 144개 슬롯과 실제 선수 이야기

구현: 국가 48개×원고 3개(144슬롯), 사실 카드 8개, 공식 출처/연도 표시. 모바일 로직 테스트에서 개수/출처/엔딩 길이 확인.

1. 48개국×3개 원고를 content.js에 입력하고 ID/중복/국가 누락 검증.
2. 표의 8개국은 ②를 검증된 선수 이야기로 교체.
3. 다른 국가는 창작 3장+다른 나라 사실 카드 1장으로 8장 표시.
4. 선택 사실 ID를 저장하여 재열람 시 동일한 이야기 표시.
5. 출처 패널·연도·창작/실제 구분 구현.

단계 완료 기준: 모든 국가에 세 슬롯, 모든 fact에 선수/실제 국가/연도/출처/검증일이 있으며 허위 직접 대사가 없음.

### P4 — 현재 자산으로 그림 연결과 모바일 정리

구현: 모바일 결과 카드 CSS, 축하 반짝임, 3개 화면 폭 검사, 나중에 넣을 이미지 경로와 누락 fallback. 새 일러스트 파일은 아직 없음.

1. 기존 캐릭터/kit와 가벼운 트로피·장면 fallback을 연결한다.
2. 사진/그림 슬롯과 이미지 실패 처리, 필요할 때만 다음 카드 preload.
3. 모바일 배치, 큰 버튼, reduced-motion, 음악·탭 복귀, 말풍선 문장 검수.
4. 아직 제작하지 않은 그림을 완료 보고에서 분명히 구분한다. 별도 이미지 제작을 무단으로 필수 gate에 추가하지 않는다.

### P5 — 검증과 브랜치 전달

완료: 모바일 로직 회귀/저장 검증 통과, JS 문법 검사 통과, 360×800·390×844·412×915 브라우저 recap 캡처와 실제 앱 부팅/콘텐츠 로드 확인. 자녀 실기기 평가 및 새 그림은 아직 없음.

아래 테스트와 모바일 캡처를 수행하고 실제 증거로 PASS/FAIL/NOT VERIFIED를 기록한다. 7세 아이가 즐거워하는지는 사용자 플레이 후 판단하며 자동 검사만으로 확정하지 않는다.

## 10. 테스트 항목과 완료 기준

### 실제 함수 기준 테스트 (`tests/mobile-logic.mjs`)

- 5번 정상 승리: 해당 round/상대/점수로 기록 5개, 결승 포함, 엔딩 7 또는 8장.
- 결승 패배: 엔딩 없음, round 유지, 재도전 가능.
- 0:0 및 2:2 승부차기 승리/패배: 기존 승리 판정 유지, 승부차기 합계와 정상 점수 분리.
- `finishMatch()` 중복 호출: 저장·round·shootout 동일, 중복 축하/기록 없음.
- 같은 상대 두 번: 두 round 모두 보존, 비교에 라운드 표시.
- 중간 국가 변경: 각 경기 homeId 보존, 마지막 팀 이야기 사용, 거짓 단일 국가 연승 문장 없음.
- 0:1 → 2:1 역전: 역전 문장. 1:0 → 2:1: 역전 문장 없음.
- 골 이벤트 없음/손상: 점수 결과는 표시, 역전 사실은 생성하지 않음.
- 기록 1개/동률/무실점/승부차기: 비교 문장 조건·동률 우선순위 정확.
- 패배 뒤 승리: 현재 round 하나만 추가. 연습 경기/튜토리얼이 저장에 영향 없음.
- 기존 round=3만 저장/불량 JSON/잘못된 국가·점수/저장 예외: 게임 부팅, 가짜 경기 없음.
- 새 컵: round=0, current 빈 배열, lastChampion 보존. 진행 중 이어하기는 현재 대회 유지.
- 우승 이야기 다시 보기: 같은 결과·동일 사실 ID, RNG 재추첨 없음.
- 48개국: 정확히 3슬롯, ID 중복 없음, 사실 8개 출처 유효, 총 카드 5~8 범위.
- content.js 로딩 실패/이미지 404: game.js 부팅 및 읽을 수 있는 fallback.
- 다음/이전 경계, 마지막 장 연타, 탭 전환: 카드 index 범위 유지, 경기 재시작/슛 없음.

### 브라우저 확인

- 360×800, 390×844, 412×915에서 첫 장·5줄 기록·비교·사실·마지막 장 캡처.
- 가장 긴 국가명/선수 문장을 확인하고 버튼/본문 잘림 없음.
- 대한민국 우승과 사실 없는 나라의 8장 우승 모두 실제 이벤트로 끝까지 넘겨 보기.
- 데이터 누락 기존 사용자 엔딩, 사진 없음/404, 음소거, reduced-motion, 탭 복귀, 새 컵 시작 확인.
- 테스트 fixture는 기존 VM/QA 내부에서만 사용한다. 공개 게임에 우승 치트 버튼이나 전역 testApi를 추가하지 않는다.
- 실제 Android 장치의 읽기 편함·음악 재개·터치 연타는 장치가 없으면 NOT VERIFIED로 보고한다.

필수 실행:

```powershell

node tests/mobile-logic.mjs
git diff --check
```

기존 visual-qa를 확장한 뒤 로컬 서버에서 엔딩 모드로 실행하고 스크린샷 경로를 기록한다. 배포 여부는 브랜치 푸시와 별개로 보고한다.

### 품질 gate

- **80%:** 부팅, 실제 결승 → 엔딩 → 새 컵 흐름, 기록/판정 정확, 카드 조작, 모바일 대표 폭, 오류 시 fallback 통과.
- **90%:** 필수 회귀 테스트 전체, 3개 폭 캡처, 문장/국가 데이터 누락 없음, 음소거/복귀/저장 예외, 불필요한 경기 로직 변경 없음.
- 이미지는 현재 fallback으로 동작할 수 있다. 새 공유 그림·아들 사진·좋아하는 선수 사진은 미제작/미제공이면 별도 미완성 자산으로 보고한다.

## 11. Luna 시작 지시와 Git 원칙

```text
docs/world-cup-ending-luna-design.md를 읽고 P1부터 순서대로 구현해줘.
먼저 repository와 최신 main을 확인하고 새 codex/world-cup-ending 브랜치를 만들어줘.
P1 재현 테스트가 현재 코드에서 실패하는 것을 확인한 뒤 수정해줘.
실제 기록에 근거한 7~8장 엔딩, 48개국 각 3슬롯, 출처 있는 선수 이야기까지 구현해줘.
기존 물리·AI·제스처·능력치·kit·튜토리얼을 유지해줘.

```

작업 전 `git status -sb`, `git branch --show-current`, `git fetch origin`을 확인한다. 깨끗한 최신 main 기반에서 새 브랜치를 만든다. 기존 변경이 있으면 보존한다. `reset --hard`, `clean -fd`를 사용하지 않는다.

Luna가 이미 구현 브랜치에서 작업을 이어가는 경우 최신 main으로 브랜치를 다시 만들지 않는다. P1~P4 작업을 보존하고 P5 테스트·캡처를 마친 뒤 결과를 보고한다. 모델 변경·커밋·푸시·PR·Pages 배포는 사용자 요청에 맞춰 진행한다.
